# 連続再生（おまかせ）の設計

2026-10-14。まだ作っていない。「ドデカのおすすめ」（`backend/app/reco/`）ができたので、その上に載せる。

## 何をするか

キューが空になったら、イリーナが次の曲を自分で選んで流し続ける。ワンタップでオン・オフ。

- 人が曲を入れたら、そちらが必ず先（おまかせの曲はキューの後ろに 1 曲ずつしか入れない）
- VC に人がいなくなったら止まる（いまの「全員退出で切断」と同じ）
- おまかせで入った曲には「おまかせ」の印を付ける（キューと再生中の表示、Discord の VC ステータスにも）

## 画面と操作

| 場所 | 操作 |
|---|---|
| 再生画面（スマホの全面・PC の右パネル） | 再生ボタンの横に「おまかせ」のトグル。オンのときはローズ |
| キューの末尾 | 「次はおまかせ: 曲名（理由）」を 1 行。×で飛ばせる |
| 曲置き場の「ドデカのおすすめ」 | 「5曲流す」の横に「このままおまかせ」（その気分でオンにする） |
| Discord | `/連続再生`（オン・オフ・状態。返事は本人にだけ） |

オンにした人と時刻を覚えておき、オンのあいだはヘッダーの接続ピルに「おまかせ中」と出す。

## 状態

- ギルドごとに `reco_kv` の `autoplay:<guild>` = `{"on": true, "mood": "now", "by": user_id, "at": iso, "count": 0}`
- 再起動をまたいで残す（レジュームと同じ考え方）。voice プロセスが読む。web の API（`POST /reco/{guild}/autoplay`）が書く
- 4 時間たつか、VC から人がいなくなったら自動でオフ（つけっぱなし防止）

## 次の曲の選び方（`reco.next_for(guild, last_key, vc_users, mood)` を 1 か所だけに）

1. 直前の曲の YouTube Music ラジオ（キャッシュ済みなら 0 秒。無ければ 1 回取る）とニコニコの関連
2. いまのおすすめ（`mood` の気分。既定は「いま聴きたい」）の上位
3. 2 つを混ぜて、次を除く: 7 日以内に流れた曲、外された曲（90 日）、直前 3 曲と同じアーティスト、15 分を超える曲
4. VC に居る人の好み（`Profile.user_tokens`）で並べ替え、上位 5 曲からランダムに 1 曲（毎回同じ流れにしない）
5. 3 曲に 1 曲は「懐かしい」から混ぜる（夜が長いと飽きるので）

選んだ理由はおすすめと同じ形で持ち、キュー・Discord に出す。

## 安全弁

- おまかせは連続 40 曲まで（それ以上は「続けますか」をアプリに出してオフ）
- 先頭の曲の取得に 2 回失敗したら次を選ぶ。5 回続いたらオフにして知らせる
- 同時に 1 曲だけ先に入れる（キューが空になる少し前、曲の残り 20 秒で次を入れる＝曲間を短くする）
- 通知は出さない（オーナーの許可制のまま）

## 学習（おすすめが育つ）

- おまかせの曲が最後まで流れた → 弱い「良い」。30 秒以内に飛ばされた → 「外した」と同じ扱い（`reco_feedback`）
- これには、再生履歴に「何秒聴いたか・飛ばしたか」が要る。`play_history` に `listened_sec` / `skipped` を足す（`music_player.py` の曲の終わりで書く。voice の再起動が要るので、人が流していない時間に別のコミットで）

## 作る順

1. `play_history` の `listened_sec` / `skipped`（voice、別コミット）
2. `reco.next_for` と単体テスト（web と同じコード。voice からは関数として呼ぶ）
3. `music_player.player_loop` の「キューが空」のところで、オンなら `next_for` → `add_to_queue(url, added_by=おまかせ)`
4. API と画面（トグル・キューの印・Discord の `/連続再生`）
5. テストサーバーで実際に 10 曲回す（`scripts/live-playback-test.mjs` を拡張）

## オーナーに決めてほしいこと

- 既定の気分（いま聴きたい / 懐かしい / 混ぜる）
- おまかせの曲に「だれ向けか」（メンバーのアイコン）を出すか
- Discord の VC ステータスに「おまかせ」と出すか
